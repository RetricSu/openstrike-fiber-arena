# Developer guide

This guide takes you from a fresh clone to a running 1v1 match in a few
minutes, then explains how the pieces fit together. For deep dives, follow
the pointers at the end.

## Prerequisites

- **Rust stable 1.85+** (the crate uses edition 2024). Install via
  [rustup](https://rustup.rs/).
- **Git with recursive submodules.** The OpenStrike engine and Pocket3D
  renderer are vendored as nested git submodules under `vendor/`. Cargo
  resolves those path dependencies on *every* invocation, so no cargo
  command works until they are checked out:

  ```sh
  git clone --recursive https://github.com/RetricSu/openstrike-fiber-arena.git
  # or, in an existing clone:
  git submodule update --init --recursive
  ```

- **Linux desktop builds only** (`--features desktop`): the wgpu/winit
  renderer needs the usual X11/Wayland development packages at build time
  and a GPU at run time:

  ```sh
  sudo apt-get install pkg-config libx11-dev libxcb1-dev \
    libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev \
    libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev
  ```

  Headless server/client builds need nothing beyond a C toolchain.
- **ripgrep** (`rg`) for the smoke-test scripts.

No Fiber node, no CKB, and no game assets are required for local
development: the server defaults to a deterministic built-in arena and the
clients can mock payments.

## Quickstart: a full match in three terminals

```sh
# Terminal 1 — authoritative server (insecure dev mode, random signing key)
cargo run --bin arena-server -- --dev-unsecure --dev-signing-key

# Terminal 2 — headless player A with mocked payments
cargo run --bin arena-client -- --name alice --dev-unsecure --mock-payments

# Terminal 3 — headless player B
cargo run --bin arena-client -- --name bob --dev-unsecure --mock-payments
```

The server waits for both players, runs the hold-invoice handshake against
the mock payment adapter, starts the match at 64 ticks/second, and logs a
settlement line for every damage bucket. Add `--auto-fire --exit-on-end` to
both clients and the match plays itself to completion.

One command does all of the above and asserts on the logs:

```sh
./scripts/smoke-local.sh
```

To *see* the game, use the native desktop client against the same dev
server — the built-in neon arena needs no external assets:

```sh
cargo run --features desktop --bin arena-desktop -- \
  --name alice --dev-unsecure --mock-payments --dev-arena
```

Headless screenshots (no window or display; handy for art iteration and CI):

```sh
cargo run --features desktop --bin arena-shot -- --out shots/arena
```

## What gets built: features and binaries

| Feature | Contents |
| --- | --- |
| *(default)* | Headless core: server, client, admin, Fiber probe. No engine/renderer deps. |
| `openstrike` | OpenStrike player/weapon simulation and Pocket3D BSP collision via `vendor/`. |
| `desktop` | `openstrike` + the native wgpu/winit renderer and first-person client. |

| Binary | Feature | Purpose |
| --- | --- | --- |
| `arena-server` | — | Authoritative 64 Hz game server; decides all damage and releases preimages. |
| `arena-client` | — | Headless client used for tests, bots, and mock matches. |
| `arena-desktop` | `desktop` | Native first-person client with prediction/interpolation and HUD. |
| `arena-admin` | — | `keygen` and `issue-token`: Netcode keys and connect tokens for production. |
| `arena-matchmaker` | `openstrike` | HTTP invite-room service; spawns one isolated server per full room. |
| `arena-shot` | `desktop` | Renders the built-in arena/duelist to PNG without a window. |
| `build-duelist` | `openstrike` | Regenerates the procedural `assets/models/duelist.glb`. |
| `fiber-probe` | — | Verifies a local FNN version, identity, and outbound channel capacity. |

## How it works in five minutes

Two networks are kept deliberately separate:

- **Renet (UDP)** carries latency-sensitive game traffic: client input
  frames up, authoritative world snapshots down, plus a reliable ordered
  channel for match setup, invoices, receipts, and preimages.
- **Fiber** carries value. Before play, each side pre-locks signed *hold
  invoices* whose SHA-256 hashes were generated by the server. When the
  server rules that damage happened, it releases the matching preimage to
  the payee, whose own local FNN settles the invoice. The victim cannot
  refuse after taking damage.

```text
Player A client ---- InputFrame ----\
                                    +--> authoritative arena server
Player B client ---- InputFrame ----/             |
                            WorldSnapshot <--------+
                                                   |
                            damage bucket -> signed preimage release
                                                   |
                                                   v
                                         payee's local FNN
                                           settle_invoice
```

Key properties:

- The server is the trusted game oracle, but it **never holds wallet keys**
  and can never take more than the invoice set both players accepted before
  play (default: 4 × 1,000 shannons per side, one per 25-damage bucket).
- Each player's own FNN parses and validates every invoice — amount, hash,
  expiry, reservation description, bound pubkey — before committing.
- A match only starts once every invoice is `Funded` on the payer side and
  observed `Received` on the payee side. Unused invoices are cancelled at
  match end.
- Channels stay open across matches; only opening/closing touches CKB L1.

Production mode replaces `--dev-unsecure` with short-lived encrypted
Netcode connect tokens (player name + fixed A/B seat + FNN identity pubkey)
and a file-backed Ed25519 settlement key; insecure defaults are never
selected implicitly. The `arena-matchmaker` HTTP service automates that
binding for public invite rooms without ever seeing a wallet key.

## Tests and CI

Every check that CI runs also runs locally:

```sh
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test                              # default features
cargo test --features openstrike        # incl. matchmaker HTTP integration test
cargo build --all-features --bins       # incl. desktop client
./scripts/smoke-local.sh                # full mock match on loopback
```

GitHub Actions (`.github/workflows/ci.yml`) runs exactly these steps on
every push to `main` and every pull request: rustfmt, clippy with warnings
denied, the test suite for both feature sets, an all-features build
(including the desktop client), a release build of the headless binaries
published as a downloadable artifact, and the headless smoke test.

The smoke scripts assert on plain-text log lines, so they export
`NO_COLOR=1` — tracing-subscriber would otherwise interleave ANSI color
codes with the field names they grep for. Keep that in mind when writing
similar log assertions.
